## Project overview

A single-page Hugo-built website that tests whether a browser can report, change, and lock the
device screen orientation via JavaScript. The deployed page is a diagnostic tool used to check
real-device/browser support for the Screen Orientation and Fullscreen APIs. There is no backend;
the output is a static site deployed to GitHub Pages.

## Commands

- Build the site: `npm run build` (runs `hugo --minify` in `./src`; output goes to `src/public/index.html`)
- Local dev server with live reload: `npm run start-server` (serves at `http://localhost:1313/`)
- Run the full test/lint suite: `npm test`

`npm test` chains these linters, all of which must pass in CI (run individually to isolate failures):

- `npm run lint` — ESLint over all JS (`npm run lint:fix` to auto-fix)
- `npm run stylelint` — Stylelint over `src/**/*.css` (`npm run stylelint:fix` to auto-fix)
- `npm run markdown` — remark over Markdown (`npm run markdown:fix` to auto-fix)
- `npm run markdownlint` — markdownlint over `src/**/*.md` and `*.md`
- `npm run package` — npm-package-json-lint over `package.json`
- `npm run json` — jsonlint over root `*.json`

There is no unit-test runner; "tests" here means the lint suite plus CI-only Lighthouse and
screenshot (`pageres`) jobs. Building requires the Hugo **extended** binary installed separately
(it is not an npm dependency).

## Architecture

The entire application is three hand-written files under `src/`, assembled by Hugo:

- `src/layouts/_default/home.html` — the only template and the whole page. Loads UIkit (CSS/JS) from
  a CDN and the local `js/code.js`. The orientation buttons are generated by ranging over
  `.Site.Data.orientations` sorted by `weight`.
- `src/data/orientations.toml` — the single source of truth for the orientation buttons. Each entry's
  `id` is passed directly to `lockOrientation(id)` as the orientation string, `title` is the label, and
  `rotation` rotates the phone image via CSS `transform`. Add or change buttons here, not in the template.
- `src/static/js/code.js` — all client logic. Key points:
  - `lockOrientation(orientation)` tries the modern `screen.orientation.lock()` first, then falls back
    to the deprecated `screen.lockOrientation` / `mozLockOrientation` / `msLockOrientation`. Every
    branch reports its result through `UIkit.notification`.
  - `toggleFullscreenMode()` wraps `requestFullscreen`/`exitFullscreen` — orientation locking generally
    requires fullscreen first.
  - `start()` reads the current orientation, subscribes to `screen.orientation` change events, and fills
    the readonly form fields. It runs only after UIkit initializes (guarded by the `uikit:init` event).
  - Functions called from inline `onclick` handlers are exported via the trailing
    `/*exported ... */` comment for the linter.
- `src/static/service-worker.js` — a near-empty service worker (no caching logic); its presence makes the
  page installable as a PWA alongside `site.webmanifest`.

`src/public/` is generated build output and is git-ignored — never edit it by hand.

## Conventions and constraints

- `src/**/*.js` is linted as browser **ES2015 script** (not modules), with `UIkit` as a read-only global.
  Root-level `*.js` config files are treated as modern Node ES modules. Keep client code within these limits.
- Deployment (`.github/workflows/hugo.yml`) triggers on push to `main`; PR checks
  (`.github/workflows/tests.js.yml`) run the lint suite across multiple Node versions plus Lighthouse and
  screenshot jobs. Hugo and Node versions are pinned in the workflow env.
